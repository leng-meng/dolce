# 源格式：文本谱（番茄简谱 / 诗歌本动态谱）

**判据全录** → [../实现/文本谱.md](../实现/文本谱.md)；语料里的规范外写法另有清单（本地私有，不入库）

## 职责

两种纯文本简谱记谱语言作为**第一等源格式**：解析、排版（原版观感）、转出其它格式、按乐句重排原文；
也是**写出目标**：任何格式打开后都能在代码区标题栏切成番茄/诗歌本原文看、另存为文本谱，识别结果同样由它写出。

## 入口

| 函数 | 文件 | 作用 |
|---|---|---|
| `parsePu(text, opts)` | `src/pu/parse.ts` | 文本 → `ScoreDoc`（对外入口；元素、音节、曲行/歌词行/文字行带原文区间） |
| `parsePuAst(text, opts)` | `src/pu/parse.ts` | 文本 → 语法树 `PuDoc`（中间结果，只给 `puToScoreDoc` 与 AST 级校验脚本） |
| `sniffDialect(text)` | `src/pu/dialect.ts:164` | 方言嗅探（打平偏番茄） |
| `puToScoreDoc(ast)` | `src/model/frompu.ts` | 语法树 → `ScoreDoc`（**无损**，`pu-scoredoc-check` 全语料逐字段还原零差异） |
| `docView(scoreDoc)` | `src/pu/slots.ts` | `ScoreDoc` → 排版行视图（原样档排版、展开档投影、双向定位共用，行里符号带 `ElementId`） |
| `jianpuInputOfDoc(doc, opts)` | `src/model/jianpuinput.ts` | → 简谱引擎输入（展开档；不带和弦/力度/多声部并排，和弦带元素 id） |
| `scoreDocToMusicXml(doc, opts)` | `src/model/toxml.ts` | → MusicXML（唯一写出端，经 `model/xmlproject.ts` 投影；保和弦/力度/多声部） |
| `layoutOriginalDocument(doc, cfg)` | `src/layout/original/compose.ts` | 原样档布局与构图（印刷原版观感）：页面树 + 音符 / 音节身份索引；由 `ScorePainter` 的原样文档请求调用，高亮 / 定位按 id |
| `layoutSong` / `layoutDocument` | `src/layout/original/place.ts` | 版面计算（定位结构） |
| `relayoutPuText(text, scoreDoc, opts)` | `src/pu/relayout.ts` | 按乐句重排**原文字符串**（读排版行视图上的原文区间） |
| `emitPu(doc, dialect)` | `src/model/topu.ts` | `ScoreDoc` → 文本谱原文，**唯一的写出端**（打开别的格式后切格式、另存为、识别结果都走它）。判据全录在 [../实现/文本谱.md](../实现/文本谱.md)「写出端」 |
| `puPhraseLines(scoreDoc, i, opts)` | `src/pu/phrase.ts` | 断点 → 新行划分 |

## 吃什么吐什么

```
pu 原文
  └─ parsePu（parsePuAst → puToScoreDoc）→ ScoreDoc ─┬─ docView ─┬─ layoutOriginalDocument →「原版」连续长图（ScorePainter）
                                                    │           ├─ jianpuInputOfDoc →「展开」（ScorePainter）
                                                    │           └─ relayoutPuText（按乐句重排原文，用视图上的原文区间）
                                                    ├─ scoreDocToMusicXml / emitJpwabc / emit123（保和弦/力度/多声部）
                                                    └─ playSourceOfSong → 试听 / MIDI

任何格式的 ScoreDoc（123 / ABC / .jpwabc / MusicXML / 识别结果）
  └─ projectForJianpu（简谱形状）→ emitPu(doc, "tomato" | "shige") → 文本谱原文
```

## 关键判据

- **方言差异全部收在 `dialect.ts::DialectSpec` 一张表里**——「**不要在两套方言之间写 if**，
  加第三种方言应该只是补一份数据」。
- **`9` 是硬冲突**：番茄是节奏音符 X，诗歌本是隐藏休止（不跟词）。**必须先定方言再解析**。
  `8` 两家一致：隐藏休止、**跟**歌词。
- 扩展名白名单 `PU_EXT = ["pu","fq","jps","txt"]`；`.txt` 太泛，嗅探失败**宁可报错不硬解**。
- 导出一律从 `ScoreDoc` 出，和弦/力度/多声部都在（《圣哉三一歌》导出 28 个 `<harmony>`）；展开档的引擎输入不带它们，本来就不画。
- 试听与谱面必须是**同一份 `ScoreDoc`**（`App.currentScoreDoc` 缓存），高亮按元素 id，重新解析会对不上。
- 原版观感用**文本谱自己的坐标系与栅格**，不沿用 `.jpwabc` 那套 `jpStackGap`。
- 前景色随一次排版的上下文（`compose.ts::OriginalCtx`）传给各画笔，不再是模块级可变量。
- **原样档的尺寸照 500 首**（用户定）：面板没给字号就按 12pt（`style/themes.ts::ORIGINAL_NOTE_SIZE`）整体缩放这套实测版式；
  长图宽同简谱原样档那张（`LONG_IMAGE_WIDTH`，150×216mm 的宽），页宽是 pt、页眉不再折算；**纸宽固定**，墨迹段在纸宽里居中（放不下才撑宽）。
  整体缩放连笔画（小节线、弧、松叶粗细、反复点）、页眉落位与首行起点一起缩（`metrics.ts::applyUserOptions`）——只缩字的话小节线比简谱引擎那一路粗出一倍。
- **源里的行放不下就整首重新断行**（`place.ts::reflowLineStarts`）：每组按歌词足额量所需宽度，全放得下照原文的行；
  有一组放不下，就把各小节的所需宽度串起来，只在小节线处断、求各行余白平方和最小（同简谱引擎），
  断点写进文档克隆的换行位（`model/breaks.ts::applyBreaks`）整份重排一遍（`compose.ts::layoutOriginalDocument`）。
  多声部文本谱（各声部小节对不齐）`applyBreaks` 不重断。
- `Fine` / `D.S.` 与小节线右对齐、基线不低于线顶一道空（`compose.ts::paintOrnaments` 的 `bar`）；段号让开首字前挂出去的引号。

## 已知限制

- 展开档不画和弦/力度/多声部（引擎输入按简谱形状投影）
- 重排**重建行结构**：原文的空行分组、`[fenye]`、行内手工留白会被覆盖（这正是该功能的语义）
- `{bz…}`/`{dsb…}` 临时层是顶层元素，断点不会切进其内部
- 重新断行后，挂在源里行首那条小节线上的 Segno 会跟着小节线留在上一行行尾（记号挂线、不挂下一小节）
- 展开档**只排一条旋律**（`Layout` 只排 `parts[0]`）
- `Space:`/`Off:` 已解析但**语义未实现**
- 原样档页脚 `BL/BC/BR` 由 `src/style/books/original.ss` 排（`-` 占位视为空）；长注释不折行，会越出版心
- `Z:` 署名按标签定词曲类型（`作词：`/`X 词曲`/`制谱：`…，`model/metakeys.ts::creatorTypeOf`），认不出的仍记作曲；原文不改
- **写成文本谱装不下的**（`model/capability.ts` 的 `tomato` / `shige` 两行，转换前列给用户）：样式表引用、演唱顺序、
  扩展 meta（没有字段可落）；音符堆只写简谱印的那个音；一条弧完全包住另一条
  （括号先开先闭，按「多连音 > 延音线 > 圆滑线」留）；比例不是 n:n−1 的多连音。番茄另外没有页眉页脚与版面指令字段
  （写了会被嗅探成诗歌本），不跟词的隐藏休止只能写成显形休止 `0`
